# TypeScript 实现决策

Python 是现有功能和数据格式的参照。TS 使用独立设计，可以按后续审核结果演进，不要求复制 Python 内部结构。

## 已实施

| 决策 | 原因与行为 |
| --- | --- |
| 全链路异步接口 | SDK、文件、进程、存储均使用 Promise；每轮 AbortController 管理取消 |
| 工具注册与统一校验 | 使用公开 JSON Schema 校验模型输入；未知字段拒绝，核心循环不再维护大段工具分派 |
| 持久化与显示事件分离 | 日志写入必须等待成功；仪表盘失败不能破坏对话记录 |
| 共享数据协议、独立代码 | 保留用户配置和 v1 日志/检查点，便于两种实现切换；TS 不依赖 Python 运行时 |
| 使用官方 MCP 客户端 | 保留 legacy 协商以连接现有服务器，独立封装限制、分页、取消和权限 |
| 更保守的验证状态 | 通过检查后，尝试已批准的编辑即标记 stale，即使最终编辑失败，也不继续宣称先前验证足够 |
| 严格新增文件大小限制 | 创建、替换和批量编辑统一为 1 MB 上限 |
| Hook 输出合计限制 | stdout/stderr 共用 16 KiB 限额，避免通过两个输出流绕过内存限制 |
| 损坏锁不自动删除 | 无法确认锁身份时提示检查，不把无法解析的锁自动视为陈旧 |
| HTTP MCP 禁止重定向 | 避免显式设置的敏感 header 被转发；服务地址应直接指向最终端点 |
| 使用 JS Unicode 正则 | 支持 JS 的 `u`/`iu` 模式；明确拒绝识别出的 Python 专属语法，错误不会静默转换 |
| 有限时的正则 worker | 正则在独立 worker 中匹配，每个文件最多 2 秒，查询最多 8,000 个字符；Ctrl+C 可终止复杂匹配，普通文本搜索仍使用异步文件扫描 |

字节上限、Unicode code point 上限和终端显示列宽分别计算。普通搜索/历史搜索的 Unicode 大小写规则遵循 JavaScript，可能与 Python 的完整 casefold 有差异；不宣称所有 Unicode、正则和 diff 排版逐字一致。

## 可单独审核的后续方案

以下方案未实施，不影响当前交付：

1. 将 CLI 和工具返回值改为结构化结果：内部返回 `{ data, error, metadata }`，由模型/UI 适配层格式化。便于 GUI 和自动化，但需要新协议版本及旧结果适配。
2. 将本地明文凭据改为系统凭据库：Windows Credential Manager、macOS Keychain、Linux Secret Service。减少凭据落盘，但需要平台依赖和无桌面环境回退。
3. MCP 支持现代 `server/discover` 协商与 OAuth：连接更多新服务，但需单独定义登录、授权、凭据存储和错误重试体验。

这些改变涉及用户行为或持久化协议，适合先审核具体方案再实施。当前功能不依赖其中任何一项。
